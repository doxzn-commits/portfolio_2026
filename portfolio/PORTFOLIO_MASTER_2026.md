## 2. [대표 프로젝트] AI 콘텐츠 자동 발행 시스템 — 클릭 20배, 전환 0→4건

**카피아 · 내부 게시판(뉴스·차량 꿀팁) 콘텐츠 그로스**

### 문제
내부 게시판은 담당자가 콘텐츠를 수기로 작성하던 채널로, 6개월간 CTA 클릭 91건·전환 6건에 그칠 정도로 성과가 정체되어 있었다. 콘텐츠별 품질 편차가 크고 발행량 확대가 구조적으로 불가능했다.

### 가설
"색인되는 글에는 공통 패턴이 있다. 이 패턴을 규칙화해 AI 생성 파이프라인에 강제하면, 발행량과 품질을 동시에 확보해 검색·AI 검색 유입과 전환을 만들 수 있다."

### 실행
- **원고 자동 생성 파이프라인**: CLI에 키워드를 입력하면 완성 HTML이 출력되는 구조 설계 (뉴스·꿀팁 2개 유형)
- **GEO 표준 템플릿**: 정답 박스, 질문형 H2, 정의형 직답, FAQ, 자사 1차 비교표, body 내부 JSON-LD(BlogPosting·FAQPage·BreadcrumbList)로 Google 및 AI 검색(AI Overview, Perplexity, ChatGPT) 인용 가능성 극대화
- **색인 규칙의 프롬프트화**: 색인 성공/실패 글을 비교 분석해 공통 패턴(제목 훅 — 숫자·순위·고유명사·연도 필수, 도입 하드데이터, 시점 고정, 고유 앵글)을 생성 프롬프트 규칙으로 체계화
- **개발 리소스 0 발행**: UI 재구축 없이 기존 raw HTML 에디터를 활용해 즉시 운영 시작
- **전환 중심 설계**: 모든 콘텐츠가 상담 CTA로 연결되도록 템플릿 단계에서 강제, 조회수가 아닌 CTA 클릭·전환으로 측정

### 성과 (2026년 6월, 동월·동일 채널 비교)

| 구분 | 수기 작성 (도입 전) | AI 자동 발행 (도입 후) |
|---|---|---|
| CTA 클릭 | 16건 | **329건 (약 20배)** |
| 상담 전환 | 0건 | **4건 (전환율 1.2%)** |

## 7. CRM 마케팅 — 앱푸시 YoY 매출 236% 증대

**핌아시아 (커머스) · 앱푸시/SMS/Email 채널 운영**

### 문제
앱푸시·SMS·Email 전 채널에서 타겟팅과 테스트 체계가 부재했고, 알림 해제율 증가·도달률 저하와 함께 매출이 감소하고 있었다.

### 실행
- **카피 구조화**: 일반적인 기획전 안내 문구를 카테고리별/상품별 유형 구조로 재설계, 상품 직접 노출·가격 USP 극대화로 전환. CTR A/B 테스트로 검증
- **타겟팅 모수 재설계**: "구매 경험 N회 이상 회원은 전환이 용이할 것"이라는 가설로 구매 이력 기반 3개 그룹 신설
- **분기별 고도화**: 1Q 타겟 그룹 개설 → 2Q 기획전별·후킹성 카피 A/B 테스트 → 3Q 클릭률 데이터 기반 메일링 디자인 폼 리뉴얼(배치 순서·디자인)

### 성과

| 지표 | 이전 | 이후 | 범위 |
|---|---|---|---|
| 앱푸시 **평균** CTR | 0.85% | **3.07%** (3.6배) | 발송 카피 전체 평균 |
| 앱푸시 YoY 매출액 | 기준 | **+236%** | 연간 |
| 대표 사례 CTR | 0.50% | **2.94%** (5.9배) | 나이키 후드티 A/B 1건 |
| 대표 사례 건당 매출 | ₩837,718 | **₩2,167,700** (2.6배) | 나이키 후드티 A/B 1건 |
| CRM 채널 매출 지수 | 1Q = 100 | **4Q = 230** (+130%) | 분기 누적 |

> ⚠️ **평균과 사례를 섞지 말 것.** 0.85→3.07%는 캠페인 전체 평균, 0.50→2.94%는 단일 A/B 사례다.
> 사례 수치를 프로젝트 대표 KPI로 인용하면 꼬리질문에서 무너진다.

- 앱푸시 카피 구조화로 **YoY 매출액 236% 증대**
- 타겟팅·카피·폼 개선 누적으로 **1Q 대비 4Q 매출 130% 성장** — 지수로는 1Q = 100 → 4Q = 230

| Redis ZSET 랭킹 | **D1 인덱스 하나** | 이 규모에 저장소를 하나 더 운영할 이유가 없음. **병목이 실제로 보이면 그때 도입** |
| 인증 벤더 | **Worker 자체 서명 토큰** | 필요한 건 "기기별 고유 신원"뿐. 익명 로그인 벤더는 과함 |
| Postgres RLS | **코드 레벨 검증** | D1은 바인딩된 Worker 안에서만 접근 가능 — 클라이언트가 DB에 직접 붙을 경로가 없음 |

**★ 가장 중요한 판단 — 위협 모델부터 정의하고 권한을 나눴다**

보안을 일률적으로 걸지 않았다. **무엇을 지켜야 하는지 먼저 정했다.**

- **랭킹 직결 필드(`best_score` 등)** → 서버만 계산·잠금
- **하트** → 클라이언트 권한. *조작해도 랭킹에 영향이 없고 광고 수익만 줄어든다. 매 판 서버 왕복하는 비용이 더 크다*

지켜야 할 것과 아닌 것을 나누지 않으면, 서버 왕복 비용만 늘고 정작 랭킹은 못 지킨다.

### 이 프로젝트가 증명하는 것

- **기획→개발→출시→심사 대응**까지 끊기지 않고 혼자 끝냈다
- 기술 선택마다 **왜 그걸 골랐고 무엇을 안 골랐는지**가 문서로 남아 있다
- 마케터가 제품의 전 과정을 직접 겪었다 — 요구사항을 받는 쪽이 아니라 **정의하는 쪽**에서

## 12. 차별점 요약

1. **숫자로 말하는 콘텐츠 마케터**: 조회수·발행량이 아니라 CTA 클릭·전환·매출로 측정하고 개선한다.
2. **GEO(AI 검색 최적화) 실전 경험**: 진단 도구를 직접 만들고, 색인 패턴을 규칙화해 20배 성장으로 입증한 국내 초기 실무자.
3. **시스템 빌더**: 사람의 반복 작업을 파이프라인으로 전환 — 콘텐츠 생성, 발행, 정산, DB 분배, 리포팅까지. 마케팅 조직의 생산성 자체를 바꾼다.
4. **풀퍼널 커버리지**: 온사이트·CRM·퍼포먼스·인플루언서·커뮤니티를 모두 실행해본 경험 위에 자동화 역량을 얹은 하이브리드.
